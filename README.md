# 巡检车上传与路网目录

路网目录与巡检车回传资料使用合成路段编号。范围以米为单位，采用左闭右开的区间；日期为当地业务日期。

使用 Node.js 22.23.4。执行 `npm ci` 后运行 `npm start`，资料源默认监听本机 4173 端口，可用 `PORT` 指定端口。

`GET /uploads` 和 `GET /network` 是可浏览的资料入口。`GET /ready` 返回当前发布序号和总发布次数。`PUT /replay` 接受 JSON `{"step":1}`，用于在联调时将来源切到指定发布时刻。发布序号从 0 开始。每次发布只列变化的来源，应答沿用上一轮存在且未被替换的地址。收到 404 并不代表之前的历史资料从业务上被撤回。重新启动服务从第 0 次发布开始。

/network 返回路线版本、线性区段、起止日期和可承接声明。anchors 的每对数值依次是来源桩号（米）和物理区段内坐标（米），表内锚点之间线性对应。不同 run 没有连续性承诺。control 列出该区段的定位校验点。carry.candidates 表示发布方列出的未确认候选。
/uploads 返回分件索引。上传实体用 vehicle、boot、seq 和 kind 识别，分件 URI 用于领取。position 是定位件，runHint 是设备填写的区段，controls 是实际观测的点。测量件用 chainage 记录起止桩号，可用 breaks 显式给出各段界点。/dispatch 是班组手上的旧派件记录，领取时间为空表示尚未发到现场。 /network/publication 在收到车端新的完结声明后公布成套行程覆盖。路网 /network 当前版最后一个 axes.from 对应的版次为当前使用版，来源分件仍按测量日和上报版标识。

运行 `npm test` 可校验资料源实际应答。样本内容存放在 `samples/`，开发时通过各来源的本地地址进行联调。
